# Algogo 이슈 작업

입력은 `ALGOGO-{번호}` 또는 작업 설명이다. 현재 대화에서 요청한 범위와 이미 승인된 내용을 유지한다. 스킬 호출 자체를 추가 외부 작업의 승인으로 해석하지 않는다.

## 공통 지침

이 스킬은 Algogo 저장소 전용이다. 스킬 디렉토리를 기준으로 아래 링크를 읽는다. 별도 워크트리로 이동한 뒤에는 그 워크트리의 루트 지침을 따른다.

1. [AGENTS.md](../../../AGENTS.md): 공통 지침, 명령 실행, 검증과 브랜치 보호.
2. [작업 절차](../../../docs/agents/work.md): 이슈 확인부터 워크트리, 구현, PR, 완료 처리까지의 기준 절차.
3. [Linear 규칙](../../../docs/agents/linear.md)과 [Git 규칙](../../../docs/agents/git.md): 프로젝트 필터, 이슈 필드, 브랜치, 커밋, PR 형식.
4. TypeScript/NestJS 수정 시 [코딩 규칙](../../../docs/agents/code.md).

위 문서를 기준으로 실행하며 같은 규칙을 이 스킬에 복제하지 않는다. 기존 Claude `/work`의 `$ARGUMENTS`에 해당하는 입력은 Codex에서는 사용자의 스킬 호출 뒤에 붙은 요청과 대화에서 얻는다.

## 실행 환경 연결

- 사용 가능한 Linear 연결 도구 또는 프로젝트 규칙의 GraphQL API를 사용한다. 키 값은 출력하지 않는다. 연결할 수 없으면 이슈를 조회하거나 갱신했다고 보고하지 말고 필요한 연결을 설명한다.
- 워크트리는 실제 Git 워크트리 경로를 확인하고 생성·사용한다. Claude 전용 `Agent(isolation: "worktree")`를 요구하지 않는다.
- 위임이 승인되었으면 제공되는 에이전트 도구를 사용하고 담당 워크트리와 수정 범위를 명시한다. 그렇지 않으면 직접 진행한다.
- 기존 작업을 이어가는 경우 브랜치·워크트리·PR·이슈의 현재 상태를 확인해 이어간다. 이미 완료된 단계를 반복하거나 중복 생성하지 않는다.
- 검증 실패나 외부 연결 문제로 완료하지 못한 단계는 명시한다. 실제 머지 완료 전에는 이슈를 Done으로 표시하지 않는다.

결과에는 작업 브랜치와 워크트리, 구현 내용, 실행한 검증, PR/이슈 링크(있는 경우), 남은 단계를 한글로 보고한다.
